---
title: 等待这件小事，AI 把它做成了算法
---

## 这本黄皮书过期了

Dan Saffer 2013 年那本《Microinteractions》给的四件套：触发器、规则、反馈、循环。按下一个静音键讲得通，因为响应在 100 毫秒内、结果可枚举。放到 AI 一次回答上立刻塞住：触发是敲 Enter,规则是跑几秒到几十秒的随机过程,反馈是一句话逐字浮现还会跳、错、回退。Saffer 那套假设界面在等用户，AI 产品反过来——界面在等模型，用户在等界面。微交互的主战场从装饰转成了不确定性的可视化。

## 一个只往前的指针

流式 Markdown 会撕裂：模型先吐三个反引号才吐 python，中间界面看到的是无效代码块,直接解析整段会闪、跳、错排。Claude Code 的 StreamingMarkdown 用一个只往前不往后的 stablePrefix 指针解决：把文本按最后一个顶层块边界切两半,前面封冻不再解析,只对最后一块每收到一个 delta 重算。代码注释写明复杂度是 O(unstable length), not O(full text)。5000 字流到 4900 字时,新算的只有最后 100 字。

## 微交互下沉到数据层

为什么这段解析算法叫微交互?因为它解决的是同一个 UX 问题——文字闪烁、布局抖动。只不过解法不在 CSS transition,而在解析器边界算法里。旁边还有两道优化:模块级 LRU 缓存让历史消息滚动时跳过约 3ms 的重解析(500 条滚一圈省下 1.5 秒卡顿);前 500 字扫不到 markdown 字符就跳过整个 lexer。结论是 AI 时代的微交互一半已经下沉到数据流处理层,给上层 React 看到的已经是稳定字符串。

## Esc 不是关闭是协作

AI 产品多了一类 Saffer 时代不存在的微交互:用户对还在跑的智能体说停一下。Claude Code 把 Esc 拆成三层语义——当前轮次取消但 agent 不死;选择模式里 Esc 只是退出选择,不关上层 agent。一个键三种意思靠上下文区分。中断后界面给一行固定高度的"被用户打断",作用不是装饰,是把中断写进对话历史,让 agent 下一轮知道自己是被否决而非被时间扔掉。信任不靠动画建立,靠"东西归你管"建立。

## 可审计纯文本

Smashing Magazine 2026 年那篇 Designing For Agentic AI 把规则总结成一句:给智能体可控性的核心,不是确认对话框,是可撤销与可审计的成本。Claude Code 的实现:CLAUDE.md 用纯文本而不是结构化配置,因为纯文本可以 git diff、可以 rm、可以人眼一秒看懂。审计和撤销不需要任何 UI 元素,只需要承认数据是用户的。一个 Esc 键、一行打断回执、一份 plain text 配置,加起来比任何确认弹窗都重。

## Spinner 没落伍

前端圈一度说 Spinner 落伍、Skeleton 才好,LinkedIn 研究称骨架屏让等待感降低 30%。但 Claude Code 全用 Spinner。原因在 Shannon:反馈设计要匹配可知信息量。列表加载知道几条几结构,用 Skeleton;AI 回答不知道时长、不知道结构、可能失败。骨架屏给用户"似乎有结构"的预期,模型慢了落差更大。Spinner 加 token 计数只如实播报:还在生成、已生成 N 个 token、上一个 token 是 X 秒前。没有预期就没有落差。

## 诚实是新美德

Material 3 Expressive 2025 年引入 spring 物理动画,时长由位移和阻尼自然决定,不再预设。官方原因写得直白:用户对静态时长的容忍度在下降,对动态自然感的偏好在上升。Google 披露一个反直觉数据:改造后参与者识别关键元素的速度提升到原来的 4 倍。Claude Code 的 spinner 走同一条路:每帧颜色和文字由实时状态决定。187 条文案管内容、stalled 红色渐变管健康度、token 计数管产出量。能播报多少状态就播报多少,诚实是新一代微交互的工程美德。
