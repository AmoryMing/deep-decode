## 标题

Codex 为什么需要一只桌宠

## 正文

2026 年 5 月 8 日前后，OpenAI 在 Codex App 的设置里新增了一个功能：桌宠（Codex pets，见 developers.openai.com/codex/app/settings#codex-pets）。第一眼看是轻功能——一个会动的小伴侣，飘在屏幕边上，偶尔提醒你它在干活。

为什么这不是装饰：它解决的是 Agent 产品里最难被传统 UI 处理的问题——长任务运行时，用户怎么知道系统还活着、在做什么、是否轮到自己接手。官方文档里关键的一句是：浮动 overlay 会在你使用其他 App 时保留 Codex 的活跃工作状态，显示当前线程，反映 Codex 是 running、waiting for input 还是 ready for review，并配一个短进度提示。桌宠的任务不是陪聊，而是把后台 Agent 的状态从一个窗口里拎出来，放到你的工作环境边缘。

这是状态拟人化：把一个抽象的进程状态，做成一个有"活着感"的形象，让用户在不盯着窗口时也能感知它。同期 Claude Code 的 agent view 走的是状态表路线，两条路解的是同一个问题。

对从业者意味着什么：当产品从"一问一答"变成"长时间后台跑"，UI 的核心任务从"展示结果"变成"持续传达系统还活着"。判断一个 Agent 产品成不成熟，看它怎么处理"用户没在看时"这段时间。
