---
title: 给 AI 一只桌宠不是卖萌
---

## 桌宠先是状态灯

第一眼,Codex 桌宠像个会动的小伴侣,飘在屏幕边偶尔提醒。但放回工作场景就不是装饰。它解决 Agent 产品最难处理的问题:长任务跑着时,用户怎么知道系统还活着、在做什么、是否轮到自己接手。官方文档说得很克制:浮动 overlay 会在你用其他 App 时保留 Codex 的活跃状态,显示当前线程,反映它是 running、waiting for input 还是 ready for review。本质上,这是一盏被拟人化的状态灯。

## 通知和窗口都不够用

传统软件的状态反馈只有两个位置:窗口内的 spinner,或系统级通知。前者要求你一直盯着窗口,后者只在离散事件弹出。Agent 不一样,它的工作是连续、长时间、带不确定性的。中间状态太多,通知会打扰;不通知,用户又焦虑。桌宠在两者之间补了一层:常驻、低噪、可扫视。它不抢注意力,但让你知道 Codex 还在场。这是 Agent UX 下一层竞争的真问题。

## 工作型而非养成型

对照泄露的 Claude buddy 源码能看清差异。Claude 把伴侣拆成可持久化的"灵魂"和由用户 ID 派生的"骨架",有物种、稀有度、帽子属性,合并顺序 `{...stored, ...bones}` 让骨架覆盖本地存储,用户改不了配置刷出稀有款。它要的是"这是你的那一只"。Codex 入口不叫 hatch 而叫 wake/tuck away——不是"孵化伙伴",是"唤醒状态层"。它没走情感留存的老路,而是把状态栏拟人化。

## 旁路观察者是关键架构

Claude buddy 源码最值得借鉴的不是动画,是角色边界。它在 prompt 里明确写:"a separate watcher"(你不是伴侣,伴侣是一个单独的观察者)。这是关键设计。若桌宠和主 Agent 混成一个角色,用户问一句两个角色抢答,全是噪声。旁路 watcher 只承担窄职责:观察状态、给短反馈、把复杂执行压成一眼能看懂的提示。Codex overlay 读取线程和工作状态,本质是状态订阅器,不是主任务执行器。

## 空闲时几乎不动

好的桌宠不是一直动。Claude buddy 的渲染组件空闲时走 IDLE_SEQUENCE,几乎不动只偶尔眨眼;只有有反应或被摸时才切到兴奋帧。这段代码没有神秘感,但很有产品感——它让你在余光里感到系统还在,而不是反复抢你的眼睛。一个常驻浮窗如果每帧都要表现自己,就从"低干扰反馈"退化成视觉噪声。克制,才是常驻类 UI 的核心能力。

## 界面正在被编程

官方给的自定义路径是:装 `hatch-pet` skill,重载 skills,让它创建一个受近期项目启发的新 pet。这超过了换皮肤。它把桌宠接进 Codex 的技能系统:pet 不只是预设资产,也能由本地上下文生成。更深一层,Codex 把"个性化界面"从设置项迁进了 skill 工作流。未来可定制的不只是形象,可能包括状态文案、提醒粒度、甚至不同仓库对应不同伴侣。界面层开始像工具层一样可编排。

## 常驻浮窗的泄露风险

盲区也要讲清。overlay 会在用户用其他 App 时显示活跃线程和进度提示。企业场景里,线程名称、任务提示、review 内容都可能含敏感信息。一个常驻浮窗必须有足够克制的显示策略,否则它会从"低干扰反馈"变成"低空泄露风险"。另一个隐忧是归因:桌宠越像主体,用户越容易把成功失败都投射到它身上。给 Agent 一个身体,不等于给它一个不受控人格。
