嗨，欢迎来到 AI 前沿拆解。今天我们聊一家中国地图公司在 Agent 时代做的一件事——高德把地图变成了 Skill。

你打开高德开放平台首页，最显眼的位置已经不是 API 文档，也不是 SDK 下载，而是一个叫 Skill 专区的入口。一家中文地图厂商，把 Anthropic 今年上半年才在英文圈带起来的词，原样搬上了门面。

距离 Anthropic 公开 Skills 协议规范，一个 SKILL 点 md 加一个 references 目录的极简约定，不到一个季度。高德这次推出的"个人地图 Skill"，连目录结构都是同构的。GitHub 仓库根目录是 SKILL 点 md，下面挂十三个 references 文件，对应地图初始化、标记、矢量图形、路径规划、安全这些能力分册。这不是巧合，这是协议跟随。

如果只看小红书那条视频笔记，这是一条针对普通用户的零代码功能宣发。自然语言说需求就生成专属地图，听上去像一个噱头。但是，如果把它放回高德开放平台过去十三个月的产品节奏里看，结论就完全不同了。

二零二五年五月，高德升级 MCP Server，把十二项核心能力暴露给大模型。二零二六年三月二十日，推出 Skill 专区，首批上线搜索、规划、数据可视化能力包。四月，发布 JSAPI Skills 和 SDK Skills，专门给 Cursor、Claude、Cline 这些 AI IDE 用。四月底，再补上"个人地图 Skill"，这一次直接绕开开发者，给非技术用户做。

十三个月里，高德对开发者交付物的形态改了三次：先是 API 加 SDK 文档，然后是 MCP Server，再然后是 Skill。每一次改的不是底层能力，是包装层。这是一家地图厂商，正式从"卖 API 调用次数"切换到"为 Agent 备货"的拐点信号。

[转场]

那么 Skill 到底比 MCP 多了什么？答案藏在文件结构里。

MCP Server 暴露的是工具调用接口。模型拿到一组工具签名，输入 schema、输出 schema，按需调用。Skill 暴露的是经过组织的知识包。一个 SKILL 点 md 当索引，下面挂带分类的 references。每份 reference 是一个具体场景的最佳实践、代码模板、避坑指南。

差别用程序员的话讲，是给一堆乐高零件，和给一本拼装说明书的差别。前者更通用，后者更可靠。Anthropic 把这种结构称为"渐进披露"。模型先看 SKILL 点 md 决定要不要展开对应的 reference，避免一次性把全部文档塞进上下文。这是大模型时代写文档的新范式，文档要写给模型读，不只写给人读。

接下来聊钱。这是高德官方最不愿意讲清楚的部分。

高德开放平台首页能查到的，仍然是按 QPS 和调用次数计费的 Web 服务 API 套餐。Skill 安装免费，但 Skill 调用底层 API 一定要消耗配额。配额从谁的 key 上扣？官方没有明说。

把已知信息拼一遍。个人地图 Skill 在 GitHub 公开发布，不收下载费。安装后需要在高德开放平台申请 Web 服务 key 并配置。用户用自然语言提需求，Skill 触发地理编码、POI 搜索、路径规划这些 Web API。产出物是一张完整的"个人地图"，可以扫码进高德 App，支持导航、分享、长期保存。

这套链路里，付费方有三种可能。用户自己持 key，门槛高，不现实。Agent 厂商持 key，把成本算进会员费。或者应用开发者持 key，把成本算进自家产品价格。从形态上判断，第二种和第三种最可能。

这意味着 Skill 把"调用地图"这件事，从开发者的工程任务，变成了 Agent 平台的功能模块。账单走平台和高德之间的批发协议。和 Mapbox 早年从"按 API 调用收费"演化到"按 MAU 收费"是同一个方向。当能力变成 Agent 的常驻技能，计费颗粒度从单次调用迁移到月活、会员、订阅。

对高德来说这是个划算的换法。原来按调用次数计费的天花板，是开发者数量乘 API 调用频次，增长缓慢。换到 Agent 时代，每一个接入了高德 Skill 的 Agent 平台都成了批发渠道。用户对地图能力无感，反而是好事。使用频次会上升，议价权也跟着上升。代价是失去和终端用户的直接关系。地图厂商退到水电级基础设施，这是 Mapbox 和 Stripe 已经走过的路。

第三个层面，产品。"个人地图"这个词不是高德自创的。Google 的 My Maps 服务做了十几年，逻辑是给用户一个图层管理工具，自己拉点、画线、加备注，存成可分享的链接。Felt 在二零二二年带着风投进场，把这个体验做得更现代。但所有这些产品有同一个限制，产出物是一张地图，不是一个能用的工具。

高德这次的差别，是把"个人"这件事重新定义了。

宣传里那句"产出物是高德地图 App 里一张完整的个人地图，支持导航、分享、长期保存"，把它拆开看。用户用自然语言提需求，比如"三里屯附近适合下午喝咖啡和逛街的地方"。Skill 调度后端 API 完成地理编码、POI 搜索、过滤、聚合、标注，最后渲染出一张地图，再生成二维码丢回高德 App。App 是这条链路的终点，不是入口。

这是一个微妙但要命的产品设计取舍。Felt 和 My Maps 把"个人地图"做成 web 端的协作画布，用户在网页上看完即走。高德把"个人地图"做成 App 内的资产，可以导航、可以分享、可以反复打开。前者是工具产物，后者更像内容产物。和小红书的笔记、网易云的歌单是同一类资产。

这条产品逻辑落地的难点不在 AI，而在前端。把自然语言翻译成 API 调用现在已经是熟食。难的是最后那一步，把结构化结果装成用户能直接使用的形态。一张能在导航软件里直接打开的真实地图，而不是 chat 框里的一段文字加几个坐标。这一步只有手握 App 流量的玩家做得到。Felt 没有 App，My Maps 退化成 Google Maps 里的二级功能，二者在这条链路上都缺关键一节。

最后聊几个被宣传话术压住的问题。

第一是能力边界。"自然语言说需求就行"在简单意图上成立，找个店、规划一条路。但稍微复杂一点的意图，比如"上海所有米其林店，按地铁一公里覆盖率排序，区分一星到三星"，需要多步规划、跨数据源融合、模糊语义解析。这些事情现在的大模型加 Web API 仍然容易出错，且错得不易察觉。

第二是协议的开放程度。高德选择了 Anthropic 的 Skills 形态，但官方没有声明这套 Skill 是否兼容 Anthropic 公开的 Skills 规范，还是高德私有协议。如果是私有协议，那它本质上还是一个围墙花园，只是名字叫 Skill 而已。

[转场]

那对从业者来说，今天这件事意味着什么。

地图厂商，API 货架要重新摆。开发文档作为一级入口的时代结束了，Skill 专区或者 MCP Server 变成新门面。如果你是百度地图、腾讯位置服务、滴滴地图这一档，三到六个月内必须有同等形态的发布，否则在 Agent 平台的能力清单里就没你这一栏。

Agent 应用方，把地图当 Skill 接入，比当 SDK 接入便宜得多。SDK 要写胶水代码、维护版本、处理鉴权。Skill 给一份 SKILL 点 md 加 references 进 prompt，模型自己学会怎么用。这是 Skill 协议在 Anthropic 那里的核心承诺，现在第一次有中文厂商把这条承诺兑成产品。

产品负责人，注意"个人化资产"这个新形态。"个人地图"不是孤例。可以预判同类产品会出现，个人歌单 Skill、个人收藏 Skill。所有有 App 流量、又有结构化数据的厂商，都可以走这条路把自己的内容资产 Skill 化。

好，今天就到这里。我们下期见。
