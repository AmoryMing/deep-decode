---
title: 它不卖模型,卖一个行业的默认结构
---

## 卖的不是模型

这家公司这次放出的不是一组金融提示词,而是一套可安装、可部署、可改造的行业工作流。10 个端到端 agent,7 个垂直行业插件,11 家金融数据商的连接器,两种部署方式。官方文档第一句就把它定义成"面向常见金融工作流的 ready-to-run agent templates"(可直接运行的 agent 模板)。它真正在卖的,不是模型能力,而是一个行业开工时的默认结构。

## demo 和样板间的差别

普通 demo 展示能力:总结一份 10-K、生成 DCF 模板。能力很亮,但客户带回公司后要自己回答:谁触发?读哪些数据?产物什么格式?谁审核?出错谁接管?这次给的不是单个答案,而是一整套文件结构。10 个工作流都用岗位名命名:Pitch、Meeting Prep、Earnings Reviewer、KYC Screener。这些不是技术演示的名字,是机构内部流程的名字。它在告诉客户:金融 agent 项目第一版目录,可以长这样。

## 默认结构才值钱

企业 AI 最难卖的从来不是参数,是"少走弯路"。金融场景不缺文本生成,缺的是流程太重:数据源多、格式旧、合规边界硬、审核链条长。这套仓库把问题压进三层结构:垂直插件让用户从 /comps、/dcf、/earnings 这些业务动作开始,而不是空白聊天框;数据连接器是真实业务的门,没有它 agent 只会写格式漂亮的空报告;部署形态让同一工作流先在个人台跑,再进团队台,最后挂到企业编排层后面。

## 不让你搬家

金融机构不想为了 AI 迁出自己的工作台。分析师还在 Excel 建模、PowerPoint 出材料、Outlook 处理客户邮件、Word 改 memo。这家公司的打法不是另建 AI 门户让人搬家,而是把模型塞进现有桌面。仓库里的 Microsoft 365 安装工具就是落地版:让 IT 管理员把能力部署进 Excel、PPT、Word、Outlook,还能对接 Vertex AI、Bedrock 或内部 LLM 网关,不强制只走官方 API。在 Excel 里改公式时,它能在保留格式、公式和依赖的同时解释自己改了什么。

## 它没说出口的边界

结构强不代表问题都解决了。免责声明非常重:这些 agent 只起草分析师工作产物,输出需要 qualified professional review(合格专业人士审核);不做投资推荐、不执行交易、不记账、不批准客户准入。这说明厂商很清楚红线:能生成材料不等于能承担责任。更商业的边界是连接器"may require a subscription or API key"(可能需要订阅或 API 密钥)——11 个连接器很漂亮,但企业要自己处理合同、权限、审计和数据驻留。给的是样板间,不是交钥匙大楼。

## 真正的争夺是解释权

最隐蔽的边界是路径依赖。谁先把一个行业的 agent 目录、skill 边界、连接器接口、人工签核点写成公开模板,谁就有机会成为后来者的起点。客户当然能改,但改一个已成形的结构,和从零设计,不是同一种心理成本。所以企业 AI 团队本周可以先停下"哪个模型更强"的讨论,转去问一个更具体的问题:本行业的默认工作流,正在被谁定义?模型仍重要,但行业工作流的默认目录,正在变成更靠近收入的那层产品。
