大家好，今天聊一个昨天还没在中文圈被认真讨论的产品，flipbook.page。

四月二十三号，一个前 OpenAI 研究员 Zain Shah 在推特发了一条发布推文，附了个域名。中文圈第一时间把它归到 Gamma、Tome 这一类 AI 演示工具里。归错了。

flipbook 不是又一个帮你做 PPT 的工具。它做的是一件更激进的事 —— 把整个浏览器的渲染层，换成视频扩散模型。屏幕上每一个像素，都不是 HTML 翻译来的，是模型实时画出来的。文字也是。点击跳转也是。链接这个东西在 flipbook 里不存在 —— 你点画面上的某一处，坐标喂回模型，模型生成下一帧。

发布四十八小时内，排队两小时起步。Modal Labs 看不下去过来赞助算力。Shah 自己在四月二十六号一条推文里承认：这个站本身就是一栋纸牌屋。

但纸牌屋下面押的不是产品，是命题。今天就拆这件事。

第一件事，flipbook 和 Gamma 根本不是同一品类。

Gamma、Tome 这一类工具做的是一件事：让 AI 帮你填模板。模板是 HTML 写的，导出是 PDF 或网页。AI 改的是内容，渲染层一根毛都没动。Gamma 卖八美元一个月，模式跟 Notion AI 一样 —— SaaS 加 AI 增量。

flipbook 做的是另一件事：让 AI 替代渲染层本身。

Shah 在发布推文里写得很直白：想象屏幕上每一个像素都从模型直接流式输出。没有 HTML，没有布局引擎，没有代码。就是你想看到的样子。

每个词都重要。没有 HTML 不是修辞，是技术事实 —— 你按 F12 打开开发者工具，里面看不到任何 DOM 元素，只有一个 canvas 在播视频。没有布局引擎也是技术事实 —— 字体大小、文字换行、栅格对齐，全部由扩散模型在像素层面自己决定，不存在 CSS 计算这一步。没有代码是说得最重的 —— flipbook 上你看到的那个按钮不是 HTML button 标签，是模型画出来的一块带按钮形状的像素。你点它，模型把你的点击坐标当作 prompt 的一部分，接着画下一帧。

把 flipbook 当 Gamma 对手分析，等于把 Tesla 第一辆 Roadster 拿去和混动凯美瑞比油耗 —— 测的不是同一回事。

第二件事，把 HTML 整条管线砍掉，代价不是抽象的理念冲突，是具体的功能丢失。一项一项数。

第一，没有可选中的文字。屏幕上的字是模型画的像素，Cmd+C 复制不了，浏览器找不到选区对象，划词翻译、复制到 Anki、保存到 Readwise，全部失效。

第二，没有 SEO。Google 爬虫看到的是一个空 canvas。flipbook 上的内容永远不会出现在搜索结果里。你看到一段对你有用的解释，没法分享一个链接给同事让他直接跳到那段，因为下次同事打开生成的可能就不是同一帧。

第三，没有可访问性。屏幕阅读器扫不到任何文字节点，视障用户在 flipbook 上看到的是空白屏幕加视频流声音。WCAG 标准在这里完全失效 —— 不是 flipbook 没做适配，是适配根本不可能。

第四，幻觉的隐蔽性比文本 LLM 严重几倍。Roon Labs 论坛一个用户的批评最锋利 —— 他说，flipbook 会、并且经常会，呈现错误信息却让你完全察觉不到，挖得越深，幻觉空间越大。

文本 LLM 的幻觉至少能被复制粘贴扔进搜索引擎查证。flipbook 的幻觉是图像形式的 —— 视觉媒介自带"看上去就是对的"的认知偏差，再加上你没法把屏幕上的事实复制出来。这是一种新形态的不可信信息，对它的免疫力还没在用户群里长出来。

这四件事不是可以打补丁修的。它们是用扩散模型替代渲染层这个选择的必然代价。

第三件事，技术栈。

flipbook 没有官方架构图，但拼起来很清楚 —— 底层是 LTX Studio DiT，以色列公司 Lightricks 开源的 Diffusion Transformer 视频模型；算力跑在 Modal Labs 的 serverless GPU 上；传输用 WebSocket，1080p、24 帧每秒。

这里有个值得停下来想清楚的问题：为什么必须用视频模型，而不是用 SDXL、Flux 这种更成熟的图像模型逐帧出？

看上去图像模型也行 —— 反正每一帧也是一张图。实际跑起来三件事会立刻翻车。

第一，帧间一致性。SDXL 每次推理用不同的随机噪声，同一个 prompt 跑两次出来的图细节都不一样。flipbook 的翻页动画如果用图像模型，连续两帧之间的字体、配色、布局会全部抖动 —— 用户看到的不是一个稳定界面，是一个发癫的动图。视频模型在训练时就学过连续帧之间应该有什么变化、什么不该变。

第二，点击响应延迟。图像模型每次生成一张高质量图大约两到五秒，用户在屏幕上点完会以为程序卡死。视频模型一次推理出多帧，均摊到每帧延迟低得多，而且用户看到的是动画过渡而不是黑屏 —— 体感上，像是在响应。

第三，文字稳定性。这点最反直觉 —— 单帧图像模型画字经常画歪，是因为它在静态图片里学过的文字结构和真实排版差距太大。视频模型在训练时见过的连续帧文字 —— 字幕、电视新闻、网页录屏 —— 远多于静态图，对文字结构反而更稳。

把这三件事合起来，结论很硬 —— flipbook 这个产品形态只有在视频扩散模型成熟之后才成立。它发生在 2026 年而不是 2024 年，是因为 LTX 这一代 DiT 模型刚刚把这三个指标推到可用线之上。

第四件事，Shah 真正在赌的不是产品。

他在发布推文里有最重要的一句：今天的 Flipbook 还很受限，所以我们让它围绕视觉解释来设计。等模型更准确、更有状态，这种方式能做的事会扩张 —— 甚至你以为必须用结构化 UI 的事，比如写代码。

这句话是整个产品的论点支点。"等模型更准确、更有状态" —— Shah 押的不是 flipbook 这个产品本身，是一条曲线：模型能力的提升会让用结构化 UI 的必要性逐年下降。

把它放到时间轴上看。

短期一到两年，flipbook 是玩具。最适合的场景是低信息密度、高视觉、容忍幻觉的内容浏览 —— 百科条目、儿童科普、博物馆导览、随手查询。在这个区间里它不会替代任何严肃应用，也不会消失。

中期三到五年，低信息密度的场景会被吃掉。维基百科、知乎这种"文本加排版加图"的产品形态，会被"AI 直接生成视觉解释"的产品蚕食。HTML 在这些场景里不会消失，但会从主流变成备选。

长期五年以上，HTML 不会死，但有一个三十年的假设会松动 —— "应用界面必须由人类工程师用代码写"。如果届时模型足够稳定、足够有状态、能做精确的字符级编辑，那么连写代码这件事都可能在 flipbook 这条路径上发生。Shah 的"连结构化 UI 的事都会被吃掉"不是修辞，是路线图。

这条路线图最大的不确定性不在模型能力，在交互范式。键盘鼠标是为了 HTML 这种"光标加焦点"的渲染模型设计的。如果输出层换成像素流，点击坐标加自然语言可能比键鼠更高效，也可能根本走不通 —— 这件事今天没人有答案。

最后一件事，对从业者意味着什么。

第一，"前端工程师会被 AI 取代"这个老命题需要重新分类。过去三年这个讨论被 Copilot、Cursor、v0 主导，焦点是"AI 帮人写代码"或"AI 直接出代码"。flipbook 把第三种可能性摆上了桌：AI 干脆不输出代码，直接出像素。

这三种路径的工程师替代曲线完全不同。AI 帮你写代码，会让初级前端工作量减少；AI 直接出代码，会让前端从职业变成审稿人；AI 直接出像素，会让前端在某些场景里整个工种消失，因为没有代码可写。判断你自己的位置在哪一条曲线上，比纠结会不会被替代重要。

第二，做 AI 应用的人需要重新看渲染层这个变量。过去做 AI 产品的默认假设是模型出文本，产品出 UI，UI 用 React 或 Vue 写。flipbook 把"UI 用代码写"这件事从公理变成了选项。以后做 AI 应用的时候多了一个设计变量 —— 这个产品的输出，应该是文本、还是结构化 UI、还是直接像素流？三种选择对应不同的容错率、不同的可访问性、不同的分发策略。

第三，盲区 —— 什么场景永远不会被替换。任何需要审计追溯的场景，金融交易、医疗记录、法律合同、政府文书。这些场景里 UI 不只是给人看的，还要被日志记录、被法庭质证、被监管抽检。像素流没有可序列化的事件日志，没有可比对的文本快照 —— 你没办法在五年后告诉法官，用户当时点的是这个按钮。这一类场景的 UI 工程师不会被这条曲线碰到。

判断一个场景是不是 flipbook 路径的目标，问一句话就够了 —— 这件事最后需不需要文字证据？需要，就不会被吃；不需要，就在射程内。

总结一下今天讲的事。

flipbook 不是 AI 演示工具，是用视频扩散模型替代浏览器渲染层的实验。代价是丢掉文字、SEO、可访问性，以及一种新形态的极隐蔽幻觉。技术上必须是视频模型而不是图像模型，因为帧间一致性、响应延迟、文字稳定性三件事一起决定。

Shah 押的不是产品，是模型能力曲线 —— 短期是玩具，中期吃掉低信息密度场景，长期让"应用 UI 必须由人写代码"这条三十年公理松动。

对从业者来说，这件事最重要的不是判断 flipbook 这家公司能不能活下来，而是判断你的工作场景在不在它的射程里。需要文字证据的场景永远安全，剩下的，看模型能力曲线推进到哪。

我是慕铭，下次见。
