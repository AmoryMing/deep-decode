## 标题

Markdown 没死，退回草稿层

## 正文

2026 年 5 月 8 日，Claude Code 团队成员、Anthropic 工程师 Thariq 在 X 上发了一篇文章《Using Claude Code: The Unreasonable Effectiveness of HTML》，博主 Berryxia.AI 做了中文转述。核心动作很小：他越来越不想让 Claude 输出 Markdown，而是让它直接生成 HTML 文件。

为什么这件小事值得看：它说的是 Agent 协作里的权力转移。过去 AI 产出一段文本，人类打开、修改、复制、归档——Markdown 胜出，是因为它轻、好 diff、好手改。但当"修改"这件事也交给 Claude Code，人类留下的工作不再是手改每一行，而是读、比较、调参、审阅，再把结果喂回 Agent。输出格式的标准随之变了：不再是"我能不能方便改这个文件"，而是"我能不能快速理解它并把决定反馈回去"。

Markdown 没有失宠，它只是退回了更适合自己的位置：源文件层、草稿层、可追溯层。HTML 抢走的，是"给人看的 Agent 输出界面"那一层。

对从业者意味着什么：当协作回路里人类从"编辑者"变成"审阅者"，工具链的默认产物格式就会被重新选择。判断一个格式的去留，要看人在回路里干的是哪种活，而不是这个格式本身好不好。
