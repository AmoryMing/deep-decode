嗨，欢迎来到 AI 前沿拆解。今天讲 Claude Code v2.1.139。

这次更新表面上是一串 release note：agent view、斜杠 goal、插件详情、hooks、MCP、滚轮速度、若干修复。单独看，每一条都像工具箱里多了一把小扳手。

但放在一起看，真正的变化只有一句话：Claude Code 正在从单会话助手，变成任务调度台。

过去用 coding agent，人的位置很像驾驶员。你盯着一个终端，看它下一步做什么，卡住了就接一句，跑偏了就拉回来。现在 Anthropic 在补两件事：横向并发，纵向续航。

agent view 管横向并发。斜杠 goal 管纵向续航。前者让你看多个后台 session，后者让一个 session 围绕完成条件跨多轮往下跑。

先说 agent view。

官方文档里，agent view 用 `claude agents` 打开。它不是普通会话列表，而是一个状态面板。你能看到哪些 Claude Code session 正在运行，哪些等你输入，哪些已经完成，哪些失败或停止。

这个界面最重要的变化，是把人的注意力从 transcript 里抽出来。

以前你要读整段对话，判断 Claude 到底在干什么。现在你先看状态。Running 的先放着，Needs input 的点进去 peek 一眼，Completed 的去验收，Failed 的去复盘。

这已经不是聊天软件语言，而是任务系统语言。

更关键的是，官方文档提到后台 session 可以没有终端 attached 继续跑，由独立 supervisor process 承载。需要写文件时，会进入 `.claude/worktrees/` 下的隔离 git worktree。

这个细节很重要。并发 coding agent 如果共享同一个 checkout，很快就会互相踩文件。worktree 不是装饰，是并发能成立的工程底座。

再说斜杠 goal。

很多人会把它理解成长 prompt，其实不对。长 prompt 影响的是当前这一轮，斜杠 goal 改的是 turn 和 turn 之间的连接方式。

你先写一个完成条件，比如：测试通过，lint 干净，旧 API 调用数为零，不能改无关模块。Claude 每跑完一轮，一个小模型会检查目标是否满足。如果没有满足，Claude 继续下一轮。

这里的关键词不是自动，而是可验证。

一句“帮我把迁移做完”不是好 goal。好 goal 应该像验收标准：跑哪个命令，看到什么结果，哪些边界不能碰。条件越清楚，Claude 越有可能自己跑到底。

这也是为什么斜杠 goal 支持 interactive、print mode 和 Remote Control。它把一次调用变成一个围绕目标持续推进的循环。

agent view 和斜杠 goal 合起来，人的角色就变了。

横向上，你可以同时发起多个后台任务。纵向上，每个任务不用你逐轮续命，而是围绕一个完成条件自己推进。

这就是任务调度台。人从驾驶员变成调度员：定义任务，设定边界，处理阻塞，验收结果。

v2.1.139 里还有一个小信号也值得看。release note 提到，subagent 的 API 请求会带 agent id 和 parent agent id，OpenTelemetry span 也会写入这些字段。

这个改动不显眼，但方向很硬。只要 agent 开始并发，它就必须可追踪、可归因、可复盘。否则团队根本不知道哪个 agent 做了什么，谁触发的，失败在哪里。

[转场]

当然，调度台不等于无人驾驶。

agent view 仍然是 Research Preview。斜杠 goal 的 evaluator 也不是一个独立审计系统。官方文档说，它不会自己运行命令或读取文件，只能根据 Claude 已经放进 conversation 的内容判断目标是否满足。

这意味着，Claude 必须真的把检查命令跑出来，把结果写出来。没有证据，evaluator 看不到。

权限也不会消失。自动继续一轮，不代表可以绕过文件写入、网络访问、凭据、PR 合并这些边界。团队还是需要 hooks、权限策略、worktree、CI 和日志。

成本也会换一种形态。过去大家只看一次对话用了多少 token。以后要看并发 session 的调度成本：状态摘要、goal 评估、失败复盘、合并成本，加起来才是真成本。

[转场]

这件事对从业者的启发很具体。

PM 可以把一个研发需求改写成三条可验收的 goal。不要写“完成迁移”，写“测试退出零，旧调用数为零，未修改无关模块”。

架构师可以拿低风险仓库试一次 agent view，同时派三个互不依赖的小任务，看 worktree、权限、CI 和 PR 合并路径能不能承受并发。

CTO 可以重新定义 AI coding 指标。不要只看团队用了多少次 Claude Code，要看并发任务数、阻塞响应时间、失败 session 复盘，以及 agent 产出合并成本。

工程师可以把常见长任务改成“目标条件、检查命令、不可变约束”三件套。写得越像验收标准，斜杠 goal 越能发挥作用。

平台负责人则要把 agent id、parent agent id、OpenTelemetry span 和权限日志放进同一套视图。agent 一旦并发，追责不能靠记忆。

[转场]

最后收一下。

Claude Code v2.1.139 的重点，不是多了一个 agent view，也不是多了一个斜杠 goal。重点是 coding agent 的产品形态变了。

AI coding 的下一步，不是单纯让模型更聪明，而是让任务变成可派发、可观察、可挂起、可验收的工作单元。

当这件事成立，人类就不再只是跟一个助手聊天。人类开始调度一组会工作的 agent。
