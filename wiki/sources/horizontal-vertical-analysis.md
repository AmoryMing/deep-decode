# 横纵分析法

## 一句话

**纵向追时间深度，横向追同期广度，最终交汇出判断。**

## 适用对象

- 产品 / 工具（Hermes Agent、Cursor、Claude Code）
- 公司 / 组织（Anthropic、字节跳动、OpenAI）
- 技术概念（MCP 协议、RAG、Agent 框架）
- 人物（行业关键人物的职业轨迹）

## 框架结构

### 纵向（5 项，时间轴）

1. **起源追溯**：技术/理念/需求源 + 核心推动者 + 行业环境
2. **诞生节点**：首次发布时间 + 最初形态和定位
3. **演进历程**：所有关键节点时间线（含融资 / 团队变动 / 战略转型 / 用户里程碑 / 公关危机）
4. **决策逻辑**：每个关键节点"为什么选 A 不选 B" + 约束条件
5. **叙事弧线**：起承转合，不写流水账

### 横向（4 项，同期切面）

判 3 种竞品场景：A 无直接竞品 / B 少量（1-2）/ C 充分（3+）。

6. 竞品场景判断
7. 竞品逐一深入（每个 1500+ 字：核心差异 + 用户视角 + 路线 + 优势短板 + 定价）
8. 生态位分析（版图位置 + 填补空白 + 正面竞争对象）
9. 趋势判断（12-24 月，机会面 + 风险面）

### 交汇（1 项）

10. **横纵交汇**：纵向 + 横向 → 综合判断 + 原创概念命名 + actionable insight（按读者身份分组）+ 可视化规划

## 写作风格要求（原方法论）

- 可读性优先，写成深度报道而不是咨询报告
- 叙事驱动，不是罗列驱动
- 观点必须建立在事实之上（先摆事实再判断）
- 用人话写，避免咨询套话（"赋能""抓手""打造闭环"）
- 对比要有温度（每个竞品"活成了什么样"，不只罗列功能）

## 篇幅要求

- 纵向 6000-15000 字
- 横向 3000-10000 字
- 横纵交汇 1500-3000 字
- **全文 10000-30000 字**（远大于事件 decode ~5000 字）
