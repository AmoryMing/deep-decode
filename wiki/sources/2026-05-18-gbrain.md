# GBrain（garrytan/gbrain）

> 一手：GitHub README + docs/GBRAIN_SKILLPACK.md。二手交叉验证：vectorize.io 两篇（what-is / review）、noqta.tn、fenado.ai、dev.to、AIHOT 中文摘要。X 原帖（garrytan/status/2055670533451366479）402 付费墙未取，靠多家转述交叉。

## 事实锚点

- 作者：Garry Tan，Y Combinator 总裁兼 CEO。README 自述"Built by the President and CEO of Y Combinator to run his actual AI agents"。
- 发布：2026-04-10，MIT 许可。24 小时内 5,400+ GitHub stars，X 触达 150 万+人；后续涨到 ~14,000 stars。
- "built in 12 days"。
- 生产规模（README）：17,888 pages、4,383 people、723 companies、21 cron jobs autonomously。SKILLPACK 文档另写 14,700+ brain files / 40+ skills / 20+ cron。两份文档数字不一致（版本差）。

## 架构（一手）

不是 "8 层"。README + review 一致描述为**三层**：

1. **Brain Repo**：纯 markdown 文件 + git 版本控制，作为 source of truth。
2. **GBrain Retrieval**：Postgres + pgvector（或 PGLite 嵌入式 Postgres 17.5，WASM，2 秒起库）。混合检索 = vector + keyword(tsvector) + RRF 融合 + multi-query expansion（Claude Haiku）+ 4-layer dedup。可插拔 engine（PGLiteEngine / PostgresEngine）。
3. **AI Agent Skills**：34（一处写 40+）个 markdown workflow 文件，指导 agent 行为。哲学：**"Thin harness, fat skills: the intelligence lives in the skills, not the runtime."** SKILLPACK 原话："markdown is code and your agent is a package manager."

"8 层"是 AIHOT 中文摘要的二次概括（前 4 层升级检索 / 后 4 层终身记忆+自我进化），非原项目术语。

## 核心机制

- **Compiled truth + Timeline**：每页两段。Above the line = 当前综合理解，证据变了就重写；Below = append-only 证据流，永不改只追加。直接对应 RAG 缺的"状态可更新""时间维度"。
- **Dream cycle**：11 阶段维护链 `lint→backlinks→sync→synthesize→extract→patterns→recompute_emotional_weight→consolidate→embed→orphans→purge`，cron 在用户睡觉时跑。Tan 称醒来时"系统比我睡前更聪明"。
- **Entity detection**：每条消息上跑，零 LLM——regex + 字符串匹配，"$0 in tokens"。
- 接口：CLI / MCP server（30+ stdio tools）/ HTTP。29 operations（read|write|admin），一处写 37 operations。
- 一等支持：OpenClaw、Hermes Agent；二等：Claude Code、Cursor、Windsurf（走自建 MCP）。

## 独立代码审查（dev.to / vectorize review，交叉一致）

- 三大旗舰功能（compiled truth rewriting、dream cycles、entity detection）**全部以 markdown 指令文档实现，不是可执行代码**。源码里搜不到 `rewrite` / `schedule` / `setInterval` / `timer` 关键字——"no rewrite logic, no scheduling mechanisms, no entity detection implementation"。
- MCP server 集成 12 个 critical issues，含 race conditions、NULL embedding overwrites（并发写覆盖）。
- 但基础设施"reasonably competent"：Postgres+pgvector 存储层、RRF 混合搜索、chunking pipeline 是真代码。
- vectorize review 评分：架构 5/5；集成广度 2/5；无 multi-hop 图遍历（"who has invested in companies founded by people I met at YC?" 这类查不了）；单运营者设计；需运营者手写 schema/workflow。

## 量化对比数据

- 混合检索 vs 关掉 graph 层：**+31.4 points P@5**（review 引 BrainBench）。
- review 评价："The published BrainBench numbers describe what the code actually does"——数字诚实，但"the brand halo is doing some of the work"。

## 学界记忆研究张力（交叉信源）

- RAG 作为 agent 记忆失败的三个结构原因：不能更新状态、按相似度而非真相检索、没有时间感（stateless retrieval）。
- 长期记忆核心难题：consolidate without catastrophic loss（巩固不灾难性遗忘）、retrieve by cause not similarity、reflect without entrenching errors、forget safely。GBrain 的 compiled-truth-rewrite 正面碰"reflect without entrenching errors"——重写即可能固化错误，且无回滚证据外的真值校验。
- 2026 学界路线：mem0 / FOREVER（遗忘曲线 replay）/ 单遍分层抽取——temporal +29.6、multi-hop +23.1。GBrain 恰恰承认无 multi-hop。

## 可用角度

GBrain 是否真"捅破个人 AI 天花板"：突破点是**记忆数据模型**（compiled-truth+timeline 把"真相会变"和"时间"写进结构，这是普通 RAG 没有的），不是新算法；而"自我进化/终身记忆"在实现层是 prompt 脚手架不是引擎，与学界"巩固不遗忘""按因果检索"的硬问题仍有差距。判断：架构选择对，工程兑现打折，叙事跑在代码前面。
