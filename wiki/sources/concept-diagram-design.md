# 概念图解设计原则

概念图解（concept diagram）不是信息图表（infographic），也不是简笔画。它是嵌在文章里、为一个认知点服务的编辑配图。图传达的信息等价于文字，但用视觉逻辑组织，让读者可以"看图"或"看文字"任选一条路径获取同样的理解。

## 核心定位

| 维度 | 信息图表 | 概念图解 | 简笔示意 |
|------|---------|---------|---------|
| 信息量 | 大（独立传播） | 等价于对应文字段 | 极简（一个点） |
| 设计复杂度 | 高 | 中高（杂志级） | 低 |
| 独立性 | 可脱离文章 | 半独立（发群里能get） | 依赖文章 |
| 记忆点 | 数据冲击 | 视觉隐喻 | 无 |

## 六条设计原则

### 1. 视觉隐喻先于形状

不画"框+文字"，先找概念的隐喻。

**三种手法**（Dario Paniagua, Visual Metaphors）：
- **Blend**：两个意象融合成一个图形（骨骼+灵魂 → 硬币两面）
- **Align**：两个意象并排对比（宠物模式 vs 牲畜模式）
- **Context**：把意象放在意外的语境（电子宠物坐在终端命令行里）

**概念图形词汇表**（选图形前先查）：

| 要传达的逻辑 | 图形隐喻 | 适用场景 |
|-------------|---------|---------|
| 表象 vs 真相 | **冰山**（水面上/下） | 看起来简单实际复杂、隐藏架构 |
| 二元对立/互补 | **硬币两面** / 阴阳 | 骨骼vs灵魂、旧vs新、风险vs收益 |
| 递进/进化 | **阶梯** / 火箭阶段 | 能力进化、产品迭代、成熟度模型 |
| 基础支撑 | **冰山水下部分** / 树根 / 地基 | 基础设施、看不见的工程 |
| 筛选/转化 | **漏斗** / 棱镜 | 数据管道、用户转化、信息提炼 |
| 层级/包含 | **同心圆** / 洋葱 / 套娃 | 权限层、抽象层、from外到内 |
| 平衡/权衡 | **天平** / 跷跷板 | 成本vs收益、两种方案对比 |
| 时间/阶段 | **时间轴** / 日出日落 | 项目进度、事件序列 |
| 连接/桥梁 | **桥** / 握手 | 系统集成、跨团队协作 |
| 分叉/选择 | **岔路** / 棋盘 | 决策点、A/B 方案 |
| 循环/反馈 | **飞轮** / 莫比乌斯环 | 增长飞轮、反馈循环 |
| 保护/隔离 | **盾牌** / 城堡 / 气泡 | 安全架构、沙箱、权限 |
| 生长/演化 | **种子→树** / 蝴蝶变态 | 从MVP到成熟产品 |

**选择原则**：图形的"形状"本身就能传递概念。删掉所有文字后，形状还能让人猜到在讲什么 = 好的隐喻。如果只剩一堆方块 = 失败。

### 2. 三级字号跳跃（杂志排版核心）

字号不能"渐变"，必须"跳跃"——读者一眼就能分出层次：
- **Display**（标题）：22-28px，bold，深色或反白
- **Label**（关键标签）：14-16px，medium，强调色
- **Detail**（细节注释）：10-12px，regular，灰色

**反面案例**：我之前的图里标题 22px、正文 14px、注释 12px——三级之间差距太小（8/2），视觉上没有层次感。应该拉到 28/14/10 这种比例。

### 3. White Space 是设计元素

白色不是"没画到的地方"，是主动的设计决策：
- **分组留白**：相关元素紧密，不相关元素之间留大间距（Gestalt proximity）
- **呼吸留白**：hero element 周围必须有大面积留白，让它"浮"出来
- **节奏留白**：密→疏→密，创造阅读节奏（杂志 spread 的核心手法）

**检验标准**：图里有没有一块面积超过总面积 15% 的纯白区域？如果没有，就是太挤了。

### 4. Hero Element（一眼落点）

一张图只有一个视觉最重的元素。读者的眼睛必须知道先看哪里：
- 用 **尺寸**（比其他元素大 2 倍以上）
- 用 **颜色**（唯一的深色块或强调色块）
- 用 **位置**（视觉中心或黄金分割点）

**反面案例**：我之前的图里每个框都是同样大小、同样边框粗细，视觉权重均匀分布，读者不知道先看哪里。

### 5. 颜色承载语义

颜色不是装饰，每种颜色必须对应一种含义：
- **强调蓝 #2383E2**：核心概念 / 重点
- **警告红 #EB5757**：问题 / 否定 / Before
- **辅助色**：最多再用 1 种（不是 4-5 种）

**规则**：单张图最多 2 种语义色 + 1 种灰色系。超过 3 种颜色，图就开始"乱"。

### 6. 信息等价但视觉分层

图的信息量等价于文字，但通过视觉层次组织成"快速扫描"和"深度阅读"两条路径：
- **快速路径**（2秒）：看 hero element + 标题 + 底部金句 → get 核心观点
- **深度路径**（10秒）：沿视觉引导线（箭头/颜色/proximity）逐块阅读细节

## SVG 执行规范（技术层面）

继承 [[visual-pipeline]] 的技术规范：
- 字体：`font-family="PingFang SC, Inter, sans-serif"`（中文必须在前）
- 尺寸：800 x (400-620)
- 转换：SVG → PNG 必须 scale=2
- 中文字符宽度约英文 x1.5，rect 留 20px 余量
- 不用 foreignObject（cairosvg 不支持）
- 不用特殊 unicode（会渲染为方框）

## 图的自检清单

制作完成后逐项检查：

1. [ ] 删掉所有文字后，形状本身还能传递概念吗？（视觉隐喻）
2. [ ] 字号是否有 3 级以上的明显跳跃？（不是渐变）
3. [ ] 有没有超过 15% 面积的留白区域？（呼吸感）
4. [ ] 能一眼找到 hero element 吗？（视觉落点）
5. [ ] 颜色是否不超过 3 种语义色？（简洁）
6. [ ] 2 秒扫描能 get 核心观点吗？（快速路径）
7. [ ] 发到群里不看正文，别人能理解吗？（半独立性）
