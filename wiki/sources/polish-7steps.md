# polish-7steps（中文技术散文润色标尺）

## 性质

deep-decode Phase 3.5 的评估标尺。Evaluator subagent 逐段按 7 步审阅 draft_v1，输出 polish-report.json。Generator 读报告自动改。

## 核心原则

> **改错不改味，炼字不炼魂。**

师承林清玄、刘墉一脉的台式哲理散文传统，同时熟悉当代技术写作的节奏密度。

## 7 步流程（每步只看一个维度）

### Step 1：术语精度
- 抓"听起来对但所指不同"的词（"点阵" ≠ Unicode glyph）
- 中英混用判断是否有惯用译名（glyph → 字符）

### Step 2：指代与事实
- 数词、代词回上下文核对
- 代码与正文描述要咬合（`reverse()` 对应"倒序"不是"转回来"）

### Step 3：翻译腔排毒
4 类常见直译结构——
- 否定阶梯（Not X, not Y, but Z → "不是 X，不是 Y，是 Z"）
- 被动滥用（被...所...）
- 长定语从句（一个能够...的...）
- 介词框架（对于...来说 / 在...方面）

替换方向：虚词强调（足足/竟/整整）/ 范围暗示（"走完一趟还不够"）/ 让事实裸奔（去修饰只剩数字与名词）

### Step 4：以实代虚
万能缩水词清单：东西/事情/问题/部分/方面/内容/情况——能换具体名词就换。

例：「最表层的东西」→「最外面的一层皮」（皮带喻 + 暗示里层有肉有骨）

### Step 5：节奏与动词

**骈散结合**：列举超过三项时，刻意让最后一项比前面长。三项等长 = spec list 冷；前三短 + 第四长 = 一松一紧有气口。

**炼动词**：扫所有"超过/包含/具有/实现/进行"等中性词。
- "超过" → "抵得上"（秤砣感）
- "包含" → "藏了"（发现感）
- "使用" → 具体动作（攥着/拎着/推着）

### Step 6：留白克制
删所有作者替读者做的反应——「你看多震撼」「这很惊人」「令人意外」全删。

中文审美：**事实自己说话，读者自己惊**。

### Step 6.5：加工过程不可见（2026-04-21 新增，优先级高于 Step 7）

**绝对禁止**：
- "写这篇文章的过程本身就在..."
- 任何让 vault / CLAUDE.md / wiki / schema / graph.json / SKILL.md 出现在正文
- "本文用了 LLM / AI / Claude Code 帮助写作"
- "这份调研本身就是被调研对象的 dogfood"
- 任何让"我/我们/本文/作者"出现在正文的段落

**处理原则**：整段删除或重构为领域判断，不"轻柔改写"——问题不在语气在存在本身。

**替代做法**：用具体判断 + 业内术语自然使用，替代工具链自白。

### Step 7：意象贯穿 + 声音保留

**意象贯穿**：全段立了什么核心意象（呼吸/流水/皮肉骨/秤/脚手架）？后续比喻必须收拢到这个意象上。换喻体 = 换脚手架 = 读者重搭一次。

**声音保留**：不要把作者个人化表达改成中性表述。
- "转圈的小玩意儿" 保留，不改成"加载指示器"
- "开小灶""让用户感觉不到问题" 保留，不改成"特殊处理""优化用户体验"

## 关键边界

- **段落级处理**：每次只处理一段
- **1 轮 hard stop**：改完一次就定稿，不二次评估（防修到走味）
- **Step 6.5 优先级最高**：作者个人化如果暴露加工过程，必须删

## 输出格式（Evaluator 严格产出）

```json
{
  "paragraph_id": "p_003",
  "original": "原段落全文",
  "revised": "润色后全文",
  "insights": [
    {"original": "...", "revised": "...", "rule_cited": "Step 3", "why": "..."}
  ],
  "overall_diagnosis": "本段核心问题集中在 Step 3 + Step 4..."
}
```

`rule_cited` 只能取 Step 1 / Step 2 / Step 3 / Step 4 / Step 5 / Step 6 / Step 7（注：6.5 在 polish_report 里通常用 Step 6.5 标注或在 deleted_sections 数组里）
